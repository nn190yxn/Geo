# AI 可见性运营 Sprint 重构任务清单

## 1. Sprint 契约和基础状态

- [x] 1.1 创建 Sprint 共享类型与状态枚举
  - 在 `packages/shared-types/src/index.ts` 增加 `VisibilitySprint`、`VisibilitySprintStep`、`VisibilitySprintStatus`、`VisibilitySprintMetricSummary`。
  - 类型应表达 Sprint 阶段、状态、指标摘要和现有业务对象关联 ID。
  - 类型不得包含平台密钥、cookies、storage state、浏览器 profile 路径或真实标准答案正文。

- [x] 1.2 增加 Sprint 仓储端口
  - 在后端 repository port 中增加 Sprint 读取、创建、更新阶段、更新指标和关联对象方法。
  - 保持品牌隔离和用户访问校验边界。

- [x] 1.3 增加内存仓储 Sprint 实现
  - 为 memory repository 增加默认演示 Sprint 和 CRUD 能力。
  - 确保热重载前的运行态行为与现有 memory demo 一致。

- [x] 1.4 增加 Prisma Sprint 模型和迁移
  - 新增 Sprint 表和必要索引。
  - 仅保存聚合状态与关联 ID，不保存密钥或浏览器会话敏感信息。

## 2. Sprint API

- [x] 2.1 增加 Sprint Controller
  - 提供列表、详情、创建、启动、停止和当前 Sprint 查询接口。
  - 返回统一 `ApiResponse<T>`。

- [x] 2.2 增加 Sprint 指标聚合服务
  - 从真实监测运行和分析结果计算 Sprint 指标摘要。
  - 排除品牌标准答案和内容草稿样本。

- [x] 2.3 增加 Sprint 阶段推进服务
  - 根据问题、真实回答、对照分析、内容任务、发布准备和复测结果推进阶段。
  - 缺少真实回答时保持等待状态。

## 3. 问题雷达和标准答案

- [x] 3.1 增强问题雷达 API
  - 输出问题意图、平台覆盖、业务价值、状态和 Sprint 关联状态。
  - 同一 Sprint 内按归一化问题文本去重。

- [x] 3.2 建立品牌标准答案模型
  - 独立保存高价值问题对应的品牌标准答案、证据和审核状态。
  - 不参与真实 AI 回复指标计算。

- [x] 3.3 增加标准答案生成和人工确认流程
  - 基于品牌资料生成可审核标准答案。
  - 用户确认后进入对照分析。

## 4. 对照分析和缺口任务

- [x] 4.1 增加真实回复与标准答案对照服务
  - 计算覆盖、准确性、风险表达、引用缺口和竞品压制差异。
  - 输出可解释证据和建议动作。

- [x] 4.2 生成内容缺口和优化任务
  - 将对照结果转化为内容补强任务。
  - 关联问题、标准答案、真实回复和 Sprint。

## 5. 内容资产、发布准备和复测

- [x] 5.1 将内容生成任务关联到 Sprint 缺口
  - 内容任务展示服务的问题、缺口和复测目标。
  - 生成正文需满足可审稿水平。

- [x] 5.2 将平台改写和发布准备纳入 Sprint
  - 发布前保持草稿、待人工发布或已发布状态。
  - 不生成不可访问伪链接。

- [x] 5.3 建立 Sprint 复测计划和趋势聚合
  - 复测结果关联回问题、内容资产和发布记录。
  - 展示本轮变化趋势。
